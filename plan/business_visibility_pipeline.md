# 能见度业务化数据流程改造计划

## 生产延迟优化执行方案（2026-08-06）

### 目标

在保证资料时次、数据质量和原子发布的前提下，将“上游数据更新时间到 CSV/NetCDF 发布”的正常延迟控制在 6～10 分钟；PNG 作为异步展示产物，不阻塞实时数据发布。

### 执行顺序

1. **最新时次优先**：实时链路只优先处理最新就绪时次；较旧时次进入 SQLite 补偿队列，避免先处理旧时次阻塞最新结果。
2. **接口并行采集**：省份和接口请求使用有上限的线程池并发执行，初始并发数为 6；单个省份/接口失败只影响该请求，不阻塞其他省份。
3. **图片异步生成**：CSV、NetCDF 完成后立即发布；PNG 进入后台图片任务队列，由独立 worker 生成。
4. **增加可观测性**：记录 API、解析、估算、IDW、文件发布、图片生成各阶段耗时，以及上游更新时间、生成时间和数据延迟；日志中输出每时次的 p50/p95 所需原始指标。

### 关键配置

```json
{
  "sourceReadyDelayMinutes": 2,
  "requestConcurrency": 6,
  "timeoutSeconds": 15,
  "retries": 2,
  "latestFirst": true,
  "maxBackfillSlotsPerCycle": 1,
  "asyncPlots": true
}
```

`sourceReadyDelayMinutes` 需要结合上游实际更新时间校准；若上游本身尚未产生资料，不能仅靠本地提前调度降低延迟。实时结果和后台补偿结果均使用同一套状态与原子发布规则。

### 验收指标

- 实时链路优先发布最新就绪时次，不因旧时次补偿阻塞。
- 单时次 12 个接口请求支持有界并发；任何单请求失败均有省份、接口和耗时信息。
- CSV/NetCDF 发布不等待 PNG；PNG 失败不影响数据时次成功状态。
- 每个成功时次日志包含 `source_update_time_utc`、`generated_at_utc`、`data_delay_seconds` 和阶段耗时。
- 原有解析、估算、IDW、状态、原子发布测试全部通过，并新增调度顺序、并发请求、异步图片和指标字段测试。

## 总体方案

在 `src/business/` 新建独立业务包，保留现有调试脚本不变。业务流程按“API采集 → 数据清洗与计数 → 两路能见度估算 → 两路IDW → 原子发布 → 状态记录”执行。

每轮只请求一次国家站和区域站数据，两条计算链路复用同一份清洗结果：

| 链路 | 能见度参考数据 | 区域站处理 | IDW输出 |
| --- | --- | --- | --- |
| `national` | 仅国家站实测能见度 | 所有有效区域站能见度均由国家站估算 | `data/idw_nc/national/YYYY/MM/DD/` |
| `national_and_regional` | 国家站实测 + 区域站实测能见度 | 保留区域站实测，估算其余区域站 | `data/idw_nc/national_and_regional/YYYY/MM/DD/` |

## 核心改造

### API采集

- 从JSON配置文件读取 `userId`、`pwd` 和数据目录；默认读取 `src/config/local.config.json`，命令行或 `VIS_BUSINESS_CONFIG` 环境变量可切换服务器配置。
- 通过 `dataRoot` 配置服务器数据根目录，并可分别覆盖 DEM、CSV、NetCDF、状态库、锁文件和日志路径；相对输出路径均相对于 `dataRoot`，相对 `demPath` 相对于项目根目录。
- 增加广东省遮罩绘图模块；两路IDW各输出一张PNG到 `visImgRoot/YYYY/MM/DD/`，边界文件由 `guangdongBoundaryPath` 配置。
- 每个资料时次分别请求广东、广西、湖南、江西、福建、海南六个省份的国家站和区域站接口，按站号合并去重后统一参与估算和IDW，以减少广东边界站点稀疏造成的插值异常。
- 分别调用 `getSurfAutoOrg4Prov` 和 `getSurfAwstOrg4Prov`，查询时间统一使用带时区的 UTC `YYYYMMDDHHMMSS`。
- 正确解析接口特有格式：首行为数量标记，第二行为CSV表头；验证必需字段并使用URL编码传参。
- 国家站能见度读取 `V20001`，区域站读取 `V20001_701_01`，沿用现有缺测值、字段映射和数值算法。
- 当主能见度字段在某时次缺测时，国家站逐行回退到 `V20001_701_01`，区域站逐行回退到 `V20001`，避免接口某一产品列暂时缺测导致整批任务失败。
- 单次请求超时60秒，最多尝试3次，退避2秒、4秒；失败不更新成功处理基线，不在日志中输出账号、密码或完整URL。

### 数据清洗与重算状态

- 按站号去重，优先保留必需字段最完整、更新时间较新的记录。
- 分别记录三个去重后的有效样本数：国家站有效能见度、区域站有效湿度、区域站有效能见度。
- 使用 `data/business/pipeline_state.sqlite` 持久化每个资料时次的最近观测计数、最近成功处理计数、状态、错误和输出路径。
- 首次发现有效数据，或任一计数高于上一次成功处理计数时，同时重跑两路估算和IDW；计数相同或下降时跳过。
- 处理失败时不推进成功计数，保证下一轮能够重试。

### 两路输出

- 估算CSV也按日期分层：
  - `data/vis_estimated_base_nation_station/YYYY/MM/DD/station_vis_all_estimated_YYYYMMDDHHMM.csv`
  - `data/vis_estimated_base_nation_and_regional_station/YYYY/MM/DD/station_vis_all_estimated_YYYYMMDDHHMM_national_and_regional.csv`
- NetCDF文件：
  - `data/idw_nc/national/YYYY/MM/DD/visibility_anisotropic_idw_YYYYMMDDHHMM.nc`
  - `data/idw_nc/national_and_regional/YYYY/MM/DD/visibility_anisotropic_idw_YYYYMMDDHHMM.nc`
- 保持现有估算参数（4个近邻、湿度/距离各占0.5）和IDW参数（β=10、p=2、6个近邻）。
- 能见度数值继续使用米，与现有生产数据和评估流程兼容；NetCDF的 `units` 修正为 `m`，并增加资料时次、生成时间、数据源类型和站点计数属性。
- 四个结果先写临时文件；两路均成功后再用原子替换发布，避免读取到半成品。

### 调度与运行入口

- 提供 `python -m src.business serve` 常驻调度模式，以及 `python -m src.business run-once` 单轮执行模式。
- 常驻模式固定在每小时 `02、07、12、17、22、27、32、37、42、47、52、57` 分启动。
- 每轮扫描 UTC `[当前时刻-30分钟, 当前时刻-5分钟]` 内所有对齐到5分钟的资料时次，按时间从旧到新处理。
- 使用跨进程非阻塞文件锁；发现上一轮仍在执行时整轮跳过并记录日志。
- 支持 `--now` 注入当前时间用于补跑和测试，支持 `--dem-path` 覆盖默认 `h:\data\DEM\merged_dem_data.nc`。
- 增加滚动业务日志，并更新README中的启动方式、配置、目录结构和故障排查说明。

## 接口与类型

- CLI命令：`serve`、`run-once`。
- API客户端返回规范化的国家站、区域站 `DataFrame` 以及接口数量标记和三个有效样本计数。
- 单时次处理返回结构化结果：资料时次、状态（成功/无增长跳过/锁冲突/API失败/计算失败）、计数和四个输出路径。
- 不修改现有调试脚本的调用方式和历史输出。

## 测试与验收

- API解析：覆盖数量首行、UTF-8中文表头、缺失字段、重复站号、缺测值、超时及重试。
- 时间调度：验证02、07、12…57分启动的严格30分钟窗口、5分钟对齐、跨小时/跨日和UTC转换。
- 重算状态：覆盖首次处理、任一分项增加、计数不变、计数下降、失败后相同计数重试。
- 双路算法：验证国家站链路不使用区域站实测作为参考；联合链路保留区域站实测并只估算其余站点。
- IDW回归：使用小型DEM和固定站点数据，对照现有算法验证网格形状、数值和单位。
- 集成测试：模拟两个API，确认一次运行生成日期分层的2个CSV和2个NetCDF；相同计数再次运行不改写文件。
- 并发测试：同时启动两个 `run-once`，确认仅一个获得锁，另一个安全跳过。
- 验收标准：任何成功资料时次均完整产生四个结果文件和成功状态；接口或任一路计算失败不得发布半成品或丢失后续重试机会。

## 假设与默认值

- 默认省份为广东、广西、湖南、江西、福建、海南，接口资料时次使用世界时，调度分钟使用服务器本地时钟；可通过命令行覆盖为单省份或自定义逗号分隔省份列表。
- API原始响应不长期落盘，仅保留规范化估算CSV、NetCDF、状态数据库和日志。
- “样本增加”以去重并完成必需字段清洗后的有效站点数为准，而不是接口首行记录数。
- 本次只改造能见度估算与IDW环节，不调整DEM生成、调试可视化和模型评估流程。
